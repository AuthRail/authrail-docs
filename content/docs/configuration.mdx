The application and sidecar need different connection settings because they
have different jobs. The sidecar downloads rules for a deployment and reports
its decisions. Your application signs requests to that sidecar and keeps the
credentials used by the business function. For an invoice reader, this means
the provider credential remains in the application while the sidecar receives
only the information needed to check its rules.

Guided [Docker](/docs/docker) or [native setup](/docs/native) creates the private
files below and prepares helpers for Node.js, Go and Python. Use this reference
to understand those files or when your operator manages the process through
existing deployment tooling. The [identity guide](/docs/identity) explains how
the keys relate to the caller and target of a request.

## Guided setup files

| File | Owner and purpose |
| --- | --- |
| `connection.json` | Setup's API origin, organisation/deployment IDs, signing-key trust and application-key binding. Keep it intact. |
| `integration.json` | Selected action versions and integration guidance. It does not itself grant permission. |
| `executor-private.pem` | Protected application only; signs requests and execution reports. |
| `executor-public.pem` | Registered in AuthRail and supplied to the sidecar for verification. |
| `deployment-token` | Sidecar's deployment-scoped credential for configuration/reporting. |
| `adapter-token` | Local application-to-sidecar credential; distinct from the deployment credential. |
| `authrail_binding_v1.*` | Generated helpers for reading the private files from the protected application. |
| `native-state` / Docker volumes | Persistent rule cache, report queues and recovery state. Preserve the complete set. |

The `--directory` option chooses where setup writes these files. The guides
use `$HOME/.local/share/authrail/my-deployment`; if you use the default location,
look for the directory printed by setup. Your operator should keep it private
and preserve it across restarts, including the keys, queued reports and
recovery information.

The environment settings below are for an operator-managed Runtime process.
Guided setup prepares its own configuration, so exporting an additional variable
in your shell will not automatically pass it into the child process or container.

## Copy these values from AuthRail

Open <a href={AUTHRAIL.clientOrigin}>AuthRail</a>, select your AI system's deployment,
then **Integration setup → Configure the
sidecar**. Copy the API address, organisation ID, deployment ID and trusted
signing-key fingerprint. Under **Get a deployment token**, select **Create
token** and save its one-time value privately.

<ProductShot src="/screenshots/runtime-integration-setup.jpg" alt="Integration setup showing deployment connection settings, application public key and token controls" caption="Connection settings come from this deployment's Integration setup. Use your own values; a saved token is not displayed again." />

| Sidecar setting | Value to use |
| --- | --- |
| `AUTHRAIL_CONTROL_PLANE_URL` | <a href={AUTHRAIL.apiOrigin}>{AUTHRAIL.apiOrigin}</a>, the API address shown as **AuthRail URL** in setup. Use HTTPS; plain HTTP is accepted only for local-loopback development. |
| `AUTHRAIL_ORGANISATION_ID` | **Organisation ID** from setup. |
| `AUTHRAIL_DEPLOYMENT_ID` | **Deployment ID** from setup. |
| `AUTHRAIL_TRUSTED_KEY_SHA256` | **Trusted signing key** from setup. Keep both displayed fingerprints during a key change. Do not get this trust value from an unverified bundle. |
| `AUTHRAIL_DEPLOYMENT_TOKEN` | The new token created under **Get a deployment token**. The sidecar uses it to connect to this deployment. |

## Prepare these values locally

Your application operator supplies the local token, key files and storage
location. The [identity guide](/docs/identity) includes manual provisioning
steps for teams that manage these through their existing tools:

| Sidecar setting | Value to use |
| --- | --- |
| `AUTHRAIL_ADAPTER_TOKEN` | The random `adapter-token` value shared only by the protected application and sidecar. Use at least 32 characters and keep it separate from the deployment token. |
| `AUTHRAIL_EXECUTOR_PUBLIC_KEY_FILE` | The path to `executor-public.pem`, whose public key you registered in AuthRail. The application keeps the matching private key. |
| `AUTHRAIL_STATE_FILE` | A private state-file path for this instance. Docker uses `/var/lib/authrail/state.json` and a volume for the whole parent directory. |

The SDK uses the organisation and deployment IDs, adapter token, private
signing key, Operation Version ID and local sidecar address. These settings
belong in the protected application. Keep them and its provider credentials
out of agent prompts, browser bundles and source control.

## Optional process settings

Most installations can use the default local address, `127.0.0.1:7078`, and
the five-second configuration update interval. Process logs work without a
separate monitoring service. The options below let an operator change these
settings, rotate keys or connect an existing monitoring system; see
[monitoring](/docs/operations) for help interpreting the output.

<details className="guide-details">
<summary>Listener, sync, key rotation and operator settings</summary>

| Setting | When to use it |
| --- | --- |
| `AUTHRAIL_HEALTH_ADDR` | Change the default `127.0.0.1:7078` to a loopback address and port chosen for this installation. Never use `0.0.0.0` or expose the listener publicly. |
| `AUTHRAIL_SYNC_INTERVAL` | Set another update interval of at least one second when the operator needs it. Default: five seconds. |
| `AUTHRAIL_PREVIOUS_EXECUTOR_PUBLIC_KEY_FILE` | Point to the previous public PEM during an approved key-change overlap while old reports drain. |
| `AUTHRAIL_OPERATOR_TOKEN` | A separate random secret of at least 32 characters for authorised local recording-gap review. It must differ from adapter and deployment credentials. |

</details>

<details className="guide-details">
<summary>Send optional diagnostics to your monitoring system</summary>

`AUTHRAIL_OTLP_ENDPOINT` is the receiving address of your own OpenTelemetry
Collector. Ask the team operating that monitoring system for its OTLP/HTTP
address; it does not come from AuthRail's Integration setup. Use HTTPS for a
remote Collector.

The sidecar sends traces, which show the path and timing of requests, and
metrics, which summarise service behaviour, to that Collector. Leave the
setting unset if your team does not use one; local process logs remain available.

</details>

<details className="guide-details">
<summary>Docker file settings and image selection</summary>

Docker's launcher can read private token files instead of direct token values:
`AUTHRAIL_DEPLOYMENT_TOKEN_FILE`, `AUTHRAIL_ADAPTER_TOKEN_FILE` and optional
`AUTHRAIL_OPERATOR_TOKEN_FILE`. Set the direct value or its `_FILE` setting,
not both for the same credential.

The repository Compose recipe takes host file paths through
`AUTHRAIL_DEPLOYMENT_TOKEN_PATH`, `AUTHRAIL_ADAPTER_TOKEN_PATH` and
`AUTHRAIL_EXECUTOR_PUBLIC_KEY_PATH`. They point to files you prepared; they are
not tokens themselves. Compose mounts these files read-only for the sidecar.
For the guided installation commands, use the [Docker guide](/docs/docker);
it does not require the repository Compose recipe.

`AUTHRAIL_SIDECAR_IMAGE` applies to the repository Compose recipe. The guided
executable selects its compiled-in image digest; see [compatibility](/docs/compatibility).
For an operator-managed rollout, choose an image digest under your team’s
change process so the installed contents stay identifiable.
Keep the entire state volume when changing images.

</details>
