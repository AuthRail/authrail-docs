---
title: "Connect Runtime to Framework proof"
description: "Qualify exact records through Control-owned Tests and Evidence."
---

AuthRail's release journey starts with an exact Framework Version. Runtime decisions can provide useful source material, but a Rail association or successful action never directly creates mapped Health or readiness.

## Follow the exact graph

Activate a Framework Version, set its scope and review its Framework Obligations. The organisation-wide boundary is the default; create a precise segment only when operation differs. Scope compiles into immutable Scope Snapshots. Unknown applicability never means that an Obligation does not apply.

Accept the Applicability Decision and Mapping to an approved reusable Control Version, with an optional scoped Implementation only for a genuine operational difference. Controls and Policies are organisation-owned and reusable across Frameworks.

The accepted path is:

```text
Exact source → immutable Framework Version → Framework Obligation
  → accepted Applicability Decision → accepted Mapping
  → approved Control / optional Implementation Version
  → Tests and Control-owned Evidence → exact Mapping-bound Health
  → Obligation Readiness → Framework Readiness
```

Aggregate Control Health is a rollup. A contextual link cannot bypass the exact Mapping.

## Define what Runtime records qualify

For example, a Control-owned Test could ask: during the review period, did every covered refund above USD 100 obtain approval before a reported execution? Its definition must state the exact Operations and deployment modes, required coverage, decision and receipt sources, period, completeness, review and freshness. Observe-only decisions cannot establish that enforcement occurred.

Collect the matching exact records and evaluate the expectation. Missing receipts, unknown outcomes, uncovered paths and gaps remain visible. Error is not pass, stale is not current and empty expectations never establish Health. A retained certificate may support integrity; it cannot establish complete provider execution by itself.

A qualified Test result or reviewed Evidence enters the existing Control-owned flow. Do not create a passing Test from a management-plane Observation or treat an AI summary as human approval.

## Remediate without rewriting history

A Finding identifies a gap. A Task organizes work to address it. An Exception governs a narrow, time-bounded accepted deviation. Completing a Task or approving an Exception does not rewrite the source Finding. Readiness remains derived, explainable and time-bounded.

Produce retained audit output using the installed product's supported report flow and exact sources. A readiness percentage, report, attestation or Runtime certificate is never legal certification. Framework acceptance, automated checks, staging acceptance and production validation remain distinct gates.
