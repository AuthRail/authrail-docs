AuthRail connects two tasks: governing AI-requested actions and maintaining an explainable Framework-led compliance journey. Runtime checks proposed tool calls against published Rails. The compliance workspace connects exact Framework Obligations to reusable Controls, Tests and retained Evidence.

A decision says whether an action may proceed. An execution receipt says what a protected application reported. Independent provider read-back can establish an external effect. These are different claims; a certificate never turns them into legal certification.

## Choose your starting point

- **Developers:** follow [Getting started](/docs/getting-started), then install the [Docker sidecar](/docs/docker) and connect [Node](/docs/node), [Go](/docs/go), or [HTTP](/docs/http).
- **Business administrators:** understand [identity](/docs/identity), [Rails](/docs/rails), and the move from [Observe to Enforce](/docs/modes).
- **Reviewers and operators:** learn [approvals](/docs/approvals), [execution and recovery](/docs/recovery), and [the retained records](/docs/records).
- **Compliance teams:** start with [Framework proof](/docs/framework-proof). A Runtime record contributes only through an accepted Control-owned Test or Evidence contract.

## Where AuthRail runs

The AuthRail control plane manages identity, reviewed Operations, versioned Rails, approvals and history. A customer-side **sidecar** receives signed deployment configuration and evaluates locally. A language adapter places checks at the actual tool boundary. The customer's **protected executor** keeps provider credentials and performs the business operation.

The sidecar does not replace a workflow engine, hold the provider write credential or execute every operation itself. If the agent has another path to those credentials or tools, a healthy sidecar cannot make that path protected. Read [the security boundary](/docs/security) before claiming enforcement.

## Current delivery status

These guides describe the source implementation and its explicitly identified validation limits. Docker packaging, Node/Go parity and the OpenShell path are being integrated. No public release matrix or complete production acceptance is implied. Pin compatible source revisions or verified immutable artifacts together; see [Compatibility](/docs/compatibility). Python is optional follow-up work. A first-party Runtime MCP adapter is outside the current delivery scope.
