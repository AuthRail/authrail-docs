**Observe** lets you see how your Rails respond while the application continues
its normal work. **Enforce** makes the application wait for permission before
running the connected function. Each deployment uses one of these two modes.

For example, a payment outside your rules can still happen in Observe, alongside
a **Would deny** decision. In Enforce, that denial stops the function you
connected. This makes Observe useful for understanding a rule before enabling
it, provided the requests themselves are safe to run.

## Move an application from Observe to Enforce

Start in a safe application or provider test account. You will compare the
rules' decisions with the function's real behaviour, then enable enforcement
once its route and credentials are in place.

### 1. Observe representative requests

In <a href={AUTHRAIL.clientOrigin}>AuthRail</a>, open **AI Inventory** and confirm the AI system and deployment, then choose the
published action and Rails it should use. Connect the application's Observe
adapter at its call and result hooks, following the [SDK guide](/docs/getting-started).
Check [compatibility](/docs/compatibility) when choosing a rule that requires
an additional reader, processor or contextual assessment.

Try requests the rule should allow, deny or send for approval, together with
any relevant missing-data case. Open their Actions and compare the advisory
checks with what the application actually did. A passing draft example alone
cannot show that these hooks receive the application's calls.

### 2. Connect the function that performs the work

The developer now uses the Enforce adapter around the business function. The
application authenticates the caller, selects the resource and provider account,
and keeps the credential away from the agent. Review other routes to the same
tool so an agent cannot go around this function; [execution security](/docs/security)
explains that review.

Check that the selected Rails cover the action and that AuthRail has the call
and result reports needed by the deployment's setup. The application code and
deployment mode work together: changing the dashboard setting cannot turn an
Observe wrapper into an Enforce wrapper.

### 3. Turn on Enforce

Open the deployment's **Overview**, choose **Review Enforce setup**, and read
its readiness information. Confirm the function and credential arrangements,
then choose **Turn on Enforce**. Wait for the sidecar to receive the Enforce
configuration before relying on it.

Run an allowed and a denied request. The allowed one should show its decision,
execution reports and result check. For the denied one, also inspect the
application's business history or provider account to confirm the function did
not create an effect. You now have evidence of both the decision and the route
that applies it.

## Call the function through the SDK

The example below reads an invoice through your existing `invoiceService`.
Create the client with the private settings from the [Node.js](/docs/node),
[Go](/docs/go) or [Python](/docs/python) guide. `operation` supplies the Operation
Version ID, a stable business request key and the caller and resource identities
obtained by the application.

Place this call in your request handler in place of its direct invoice read.
The SDK invokes the function only after the call check succeeds, then checks
its result before returning it. If the wrapper reports an error, return or
handle that error rather than calling the invoice service again outside it.

<Tabs items={['Node.js', 'Go', 'Python']} groupId="sdk-language" persist>

<Tab value="Node.js">

```ts
import { EnforceClient } from '@authrail/sdk-node';

const client = new EnforceClient(privateClientConfig);
const checked = await client.enforce(
  operation,
  { invoiceId: invoice.id },
  (arguments_) => {
    if (typeof arguments_.invoiceId !== 'string') {
      throw new Error('invoiceId must be text');
    }
    return invoiceService.read(arguments_.invoiceId);
  },
);
return checked.result;
```

`privateClientConfig` comes from the Node setup. `invoiceService` belongs to
your application; the SDK does not create a provider connection for it.

</Tab>

<Tab value="Go">

```go
result, _, _, err := authrail.Enforce(
    ctx, client, operation,
    map[string]string{"invoiceId": invoiceID},
    func(ctx context.Context, args map[string]string,
        execution authrail.ExecutionContext) (map[string]string, error) {
        return invoiceService.Read(ctx, args["invoiceId"])
    },
)
if err != nil {
    return nil, err
}
return result, nil
```

Import `context` and `authrail "github.com/AuthRail/authrail-sdk-go"` and use
the client from the Go setup. This example returns `map[string]string`; your
function can use its own JSON result type.

</Tab>

<Tab value="Python">

```python
from authrail import ExecutionContext, JSONObject

async def read_checked_invoice(arguments: JSONObject,
                               execution: ExecutionContext) -> JSONObject:
    invoice_id = arguments["invoiceId"]
    if not isinstance(invoice_id, str):
        raise ValueError("invoiceId must be text")
    return await invoice_service.read(invoice_id)

# client is an AsyncEnforceClient configured as in the Python guide.
checked = await client.enforce(
    operation, {"invoiceId": invoice_id}, read_checked_invoice
)
return checked.result
```

Use the `AsyncEnforceClient` from the Python setup inside your async request
handler. `invoice_service` is your application's existing reader.

</Tab>

</Tabs>

These examples use the core Enforce wrapper. Requirements such as automatic
Data reads, ready-made Guard processing and Contextual AI also need the
capabilities listed in [compatibility](/docs/compatibility). For a function
that changes data, save the callback's execution context and use its provider
idempotency key as described in [recovery](/docs/recovery).

## Handle a wait or an unavailable check

An approval-required response means the function is waiting for a person's
decision. Save the work using an [approval continuation](/docs/approvals#save-and-resume-the-applications-work)
so the originating application can resume it later. A denied request, expired
permission, uncovered action or unavailable sidecar stops Enforce before the
function runs. The required call report must also have reached AuthRail; a
report waiting only in the local queue does not yet satisfy that condition.

Result checks happen after the function, which is why a withheld result can
accompany a completed business operation. If execution or reporting leaves the
effect uncertain, [investigate the original attempt](/docs/recovery) before
retrying. Returning an error to the agent does not by itself establish that a
provider made no change.

<details className="guide-details">
<summary>What Enforce establishes before running a function</summary>

The SDK needs a fresh allowed decision for the actual input, or the matching
one-use permit after approval. It records the attempt's start with AuthRail
before invoking the function and checks a successful result before releasing
it to the agent. A **retained** report is one AuthRail has acknowledged; a
**queued** report is still waiting locally for that acknowledgement.

Connecting <a href={AUTHRAIL.mcpEndpoint}>hosted AuthRail MCP</a> through the
[MCP setup guide](/docs/mcp) provides management access to configuration and
records. Business tools, shell commands and provider APIs need their own SDK
route; management access cannot add those hooks to another tool.

</details>

<details className="guide-details">
<summary>Observe during an outage and separately named deployments</summary>

Observe remains advisory when the sidecar or reporting service is unavailable.
The application can continue and report its outcome separately, while an absent
decision remains a gap in what AuthRail recorded. That execution report does
not turn an observed request into an enforced one.

You can use separately named deployments to compare modes, each with its own
identity and selected rules. There is no required Test/Live naming scheme or
third Runtime mode. If an Enforce installation stops working, repair that
installation rather than automatically changing it to Observe.

</details>
