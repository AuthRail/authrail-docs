A native sidecar runs directly on your computer or server as a separate
program. Choose it when your protected Node or Go application also runs on that
host. It checks the same rules as the [Docker installation](/docs/docker).

You will build the executable, give it your deployment settings, then leave it
running while the application makes checks. You need Git and Go 1.26 or newer.
First complete [the dashboard setup](/docs/getting-started) and
[connection details](/docs/identity), including the registered public key and
private token files.

## 1. Build the executable

Get the <a href={AUTHRAIL.repositories.sidecar}>sidecar source</a> and compile it:

<CommandBlock lang="bash" code={`git clone --branch main ${AUTHRAIL.repositories.sidecar}.git
cd authrail-sidecar
go build -o authrail-sidecar ./cmd/authrail-sidecar`} />

A successful build returns to the shell and creates `authrail-sidecar` in the
checkout. It has not started the sidecar yet.

## 2. Give it the deployment settings

In the same terminal, replace the `YOUR_...` values with those from the
deployment's **Integration setup → Configure the sidecar**. Use your own API
address if it differs from this example:

<CommandBlock lang="bash" code={`export AUTHRAIL_CONTROL_PLANE_URL=${AUTHRAIL.apiOrigin}
export AUTHRAIL_ORGANISATION_ID=YOUR_ORGANISATION_ID
export AUTHRAIL_DEPLOYMENT_ID=YOUR_DEPLOYMENT_ID
export AUTHRAIL_TRUSTED_KEY_SHA256=YOUR_TRUSTED_SIGNING_KEY
export AUTHRAIL_EXECUTOR_PUBLIC_KEY_FILE="$HOME/.local/share/authrail/my-deployment/executor-public.pem"
export AUTHRAIL_DEPLOYMENT_TOKEN="$(cat "$HOME/.local/share/authrail/my-deployment/deployment-token")"
export AUTHRAIL_ADAPTER_TOKEN="$(cat "$HOME/.local/share/authrail/my-deployment/adapter-token")"
umask 077
mkdir -p "$HOME/.local/state/authrail/my-deployment"
chmod 700 "$HOME/.local/state/authrail/my-deployment"
export AUTHRAIL_STATE_FILE="$HOME/.local/state/authrail/my-deployment/state.json"`} />

The token and key paths refer to the files from the connection guide. The
state directory stores the sidecar's rules, report queue and recovery history.
Keep it private and use a separate directory for each sidecar instance.

These settings include private credentials. Keep the terminal and process
environment outside the agent's reach. The application's private key and
provider credentials do not belong in the sidecar.

## 3. Start it

Run:

```sh
./authrail-sidecar
```

The sidecar stays in the foreground and prints startup and service messages.
Leave this terminal open. Use another terminal to start your application and
check the local service:

```sh
curl --fail --silent --show-error http://127.0.0.1:7078/health
```

Look for `bundleValid: true` and the mode selected for this deployment. The
response also shows the loaded bundle, application-key fingerprints and pending
report counts. HTTP success alone only means the endpoint responded.

If there is no valid bundle, check the copied settings, deployment token,
registered application key and selected Rails. The deployment's **Overview →
Connection health** should also show a recent update after the sidecar connects.

## 4. Connect the SDK

Follow the [Node](/docs/node) or [Go](/docs/go) guide in your protected application.
Use `http://127.0.0.1:7078` as its sidecar URL, the same adapter token, and the
application's private key. These processes must run on the same host; keep the
sidecar listener private.

After a safe request, the terminal shows decision events. The
[Runtime walkthrough](/docs/application-example) includes an actual native
status check and operation logs. [Monitoring](/docs/operations) explains how
to read those events.

<details className="guide-details">
<summary>Stop or remove the native sidecar</summary>

Pause the protected application or move its traffic to a replacement first.
If you started the sidecar in this terminal, press Ctrl+C. If a service manager
starts it, stop that specific service. Disable its automatic startup when
removing the installation.

For a background process, find its listener:

```sh
lsof -nP -iTCP:7078 -sTCP:LISTEN
```

Use the configured port if different. Confirm that the process belongs to this
sidecar, then send SIGTERM with `kill -TERM PID`, using the confirmed numeric
PID. Allow it to exit and run the listener check again. Do not stop unrelated
processes or use a broad process-name kill command.

For permanent removal, remove the stopped executable and its service-manager
entry. Keep private state and credentials until queued reports, blocked reports
and unknown effects are resolved and retained as required. Deleting the program
does not erase AuthRail's retained Actions. Do not delete state to clear a warning.

</details>

<details className="guide-details">
<summary>Package, maintain or upgrade an installation</summary>

For a maintained installation, have a service manager or secret store supply
the credentials rather than relying on an interactive terminal. Keep the
instance's identity and complete private state through restarts.

To build a local archive for another installation of the same OS and CPU, run
this from the source checkout:

```sh
sh scripts/package.sh development ./dist
```

It creates an archive and adjacent SHA-256 checksum. Verify the checksum before
unpacking. Choose a reviewed source commit when you need a repeatable build.

Before an upgrade, pause the application, stop the sidecar with Ctrl+C or
SIGTERM, and allow its bounded shutdown to complete. Preserve the entire state
directory and credential files. Replace the executable and restart with the
same settings, then check valid rules and report queues before accepting work.
Never restore an older state copy or delete rejected state to make startup
succeed. Follow [recovery](/docs/recovery) for unresolved reports and effects.

</details>
