A native sidecar runs as a separate program on the same computer or server as
your application. For example, the invoice reader in the quickstart can ask a
sidecar on your laptop to check each request against its Rails. Choose this
installation when your Node.js, Go or Python application runs directly on the
host; use [Docker](/docs/docker) when it runs in a container.

Before you begin, prepare the action, published Rail and deployment in
<a href={AUTHRAIL.clientOrigin}>your AuthRail workspace</a>, following the
[quickstart](/docs/getting-started). You also need a macOS or Linux terminal with
`curl` and `tar`. Setup connects to <a href={AUTHRAIL.apiOrigin}>{AUTHRAIL.apiOrigin}</a>. The download includes the executable, so you do not need Go or a
source build.

## 1. Download the sidecar

Choose your operating system and processor. On a Mac, **About This Mac** shows
an Apple chip or an Intel processor. On Linux, `uname -m` prints `aarch64` for
arm64 or `x86_64` for amd64.

Each download has a **checksum**, a value used to check that the archive has
not changed. The commands verify it before unpacking the program. If verification
fails, stop and download it again from the release page.

The final command prints the program’s version and build revision, then exits.
Keep this terminal in the extracted directory for setup.

## 2. Connect and start

Run this command to connect to the AuthRail API. The `--directory` option
puts the installation’s private files in a location you can reuse across restarts.

<CommandBlock lang="bash" code={`./authrail-sidecar setup --api-url ${AUTHRAIL.apiOrigin} \\
  --directory "$HOME/.local/share/authrail/my-deployment" --runtime native`} />

When the browser opens, sign in and choose the organisation and deployment
you want to connect. Setup creates the application’s signing key on your
computer and registers its public key with AuthRail. It also saves the
deployment credential, a separate token for local SDK calls, and helper files
for Node.js, Go and Python. These files belong to your application operator;
keep the private directory out of the agent’s reach.

The sidecar stays in the foreground. Wait for **Signed rules are ready**, then
leave this terminal open. Setup writes process output to `sidecar.log` inside
that private directory. In another terminal:

```sh
curl --fail --silent --show-error http://127.0.0.1:7078/health
tail -n 50 "$HOME/.local/share/authrail/my-deployment/sidecar.log"
```

Look for `bundleValid: true` and the mode you selected for the deployment.
This means the sidecar has usable rules. You will check the application itself
in the next step. If rules are unavailable, check the deployment’s selected
Rails and access, then read `sidecar.log` for connection errors. Preserve the
installation files while investigating so pending reports and recovery
information remain available.

## 3. Wrap your actual function

Continue with [Node.js](/docs/node), [Go](/docs/go) or [Python](/docs/python).
Use `http://127.0.0.1:7078` from the protected host application. The SDK uses the saved local token and private signing key. Business-provider
credentials also belong in your application, where the agent cannot read them.
Run the invoice example and open its [Action and decisions](/docs/records) to
see the complete connection working.

<details className="guide-details">
<summary>Restart, stop and preserve a native installation</summary>

Pause the protected application before stopping the sidecar. Ctrl+C stops this
foreground installation and preserves its private settings and `native-state`
directory. Restart the same saved connection without signing in again:

```sh
./authrail-sidecar installation run \
  --directory "$HOME/.local/share/authrail/my-deployment"
```

For a maintained installation, a service manager can run this command under
the application operator’s account. Stop that service before upgrading or
removing the program, and preserve the whole private directory. It contains
keys, queued reports and the information used to recover interrupted work.
Only one sidecar should use a state directory at a time; restoring an older
copy could also erase reports or roll back configuration history. See
[recovery](/docs/recovery) before replacing state or retrying an uncertain operation.

When you rerun setup, it recognises the saved deployment and key. If you have
edited a generated helper, setup keeps your version and writes the update to
a separate file for you to compare. A different registered key or missing
state needs recovery or a planned key change. Moving from native to Docker
also needs a migration of the installation; setup rejects reuse of the native
directory as a Docker installation.

</details>

<details className="guide-details">
<summary>Remote browser and listener options</summary>

Use `--no-browser` if you want to open the printed sign-in URL yourself. The
browser must be able to reach the temporary callback on the setup computer’s
loopback interface, so keep that callback private. The native `--listen` option
changes the local address and port used by the sidecar; choose a loopback address
and configure the SDK to use the same one.

</details>
