AuthRail's public repositories provide the libraries and sidecar you use to
connect an application. If you are getting started, the [quickstart](/docs/getting-started)
introduces them together through a small invoice reader. The [app-builder
guide](/docs/build-your-app) explains how the integration fits between your
agent's tool request and the function that performs the work.

## SDKs and sidecar releases

Choose the SDK for your application's language. The guides use published version
**{AUTHRAIL.releases.sdkVersion}** and show how to load your connection settings,
check a function and inspect its decisions.

| Language | Package | Guide |
| --- | --- | --- |
| JavaScript or TypeScript | <a href={AUTHRAIL.packages.node}>@authrail/sdk-node on npm</a> | [Node.js](/docs/node) |
| Go | <a href={AUTHRAIL.packages.go}>authrail-sdk-go on pkg.go.dev</a> | [Go](/docs/go) |
| Python | <a href={AUTHRAIL.packages.python}>authrail on PyPI</a> | [Python](/docs/python) |

The sidecar runs separately beside your application. Download its executable
and checksums from the
<a href={`${AUTHRAIL.repositories.sidecar}/releases/tag/v${AUTHRAIL.releases.sidecarVersion}`}>version {AUTHRAIL.releases.sidecarVersion} release</a>,
then follow [Docker](/docs/docker) or [native setup](/docs/native). The
[compatibility reference](/docs/compatibility) explains which capabilities are
included in the published versions and how the setup executable's selected
Docker image differs from the native Runtime release.

The application in the [video walkthrough](/docs/application-example) is a local
reference application for people with repository access. It has no hosted
version, and its example provider bindings do not make every provider operation

## Your organisation's AuthRail addresses

Use the workspace address supplied by the person administering your AuthRail
installation. Sidecar setup also needs the matching API origin, and an assistant
connection uses AuthRail MCP at `https://mcp.authrail.io/mcp`.
These addresses serve different purposes; the workspace or documentation URL
cannot replace the API address in a sidecar command. The [connection
guides](/docs/getting-started) explain where each is used.

## Other integration references

The optional [OpenShell integration](/docs/openshell) combines customer-operated
sandbox restrictions with AuthRail's business authorization. Consult the
<a href={AUTHRAIL.references.openshell}>official OpenShell documentation</a> and
<a href={AUTHRAIL.references.openshellRepository}>repository</a> for the sandbox's
installation and operation.

<a href={AUTHRAIL.references.openappa}>OpenAPPA</a> is an external reference for
tool-call and tool-result interception patterns. AuthRail has its own SDKs,
Rails, approvals and recovery contracts, which are described in these guides.

## Reporting a problem

When reporting an issue, include the component version, the command or task you
were performing, what you expected and a redacted error. If a decision is missing,
check whether its report is queued locally or has reached AuthRail; the
[monitoring guide](/docs/operations) explains how to find that information.
Credentials, private review links and raw customer or provider content should
remain outside public issue reports.
